# E54-ADAPTIVE-RESIDENCY：可配置分组与token预算

已部署到 H3TensorParallel 节点。旧默认 three_groups 保留；新增 manual_groups / auto_tokens。自动模式在本机 17,253、31,824、46,395 token 的真实双卡50层回放通过。仅主干回放，不是完整8步采样、VAE或端到端视频。最后补充的15s手动8/3重打包因持续主机内存压力预防性停止。

## 使用方式

手动：`weight_residency=manual_groups, num_groups=8, resident_slots=5`。自动推荐：`weight_residency=auto_tokens, resident_slots=2, residency_safety_gib=2.0`；自动模式resident_slots是上限，可改5，已测三种token仍选择2槽。num_groups仅手动模式使用。原工作流widget顺序保留，新参数追加在末尾；重启服务后可见。

每组计算完成后，用CUDA done事件保护槽位，复制流覆盖槽位并预取g+S组；不将权重写回CPU。步末最后一笔跨步预取延迟到下一步第一组，避免每步全卡同步额外等待它。末步停止跨步预取；VAE优先借足够大的闲槽，小槽则释放无用槽、预算足够时另分配，否则推迟到decode。VAE交接仅本轮合成缓冲区验证，未做新分组下完整VAE成片验证。

## 自动公式与区间

`工作区 = max(reserve_vram_gb, 3 + 0.00020 × N) GiB`；`权重预算 = 两卡较小的可用显存 - 工作区 - 2 GiB`。可用显存来自CUDA mem_get_info加可回收PyTorch缓存，非NVML total-used。枚举分组数3..25和不超过resident_slots的槽数，以最大组实际打包字节检查容量。工作区是保守经验包络，不是OOM保证。

重叠条件近似为 `(S-1) × 最短组层数 × 每层计算时间 >= 最大组字节 / H2D带宽`。估计采用5GiB/s与每层0.20×N/17000秒，实际通过下面的时间线校验。两槽已有足够重叠窗口，所以长token优先细分、腾出激活空间。N包含全部packed条件/音频/视频token。

auto现阶段限定50层H3 INT8、Kitchen50、chunk<=4096、主干内部输出original、N<=48000；超出拒绝。实际分组随可用显存变化，公式、条件和固定19GiB预算的token区间示例 (historical artifact; not bundled)、理论枚举 (historical artifact; not bundled)。

## 失败、停止与监控更正

1. 首轮55ecf94的逐组时间线钩子被/e41/events恢复覆盖，spans为空；保留普通墙钟/分配器/数值结果，不能把空spans当0等待/0重叠。根目录summary.json及n17253-timeline.png属于首轮无效分析产物，最终指标以refined/summary.json为准。初始缓存状态标签5s/10s写反，真实顺序是5s冷进程、10/15s同一进程。最终复测已修复。
2. refined最后15s手动8/3在CPU重打包阶段停止，尚未生成该配置的GPU结果。PSI full avg10约54.28%，MemAvailable仍有约54GiB以上，因此不能称RAM耗尽或CUDA OOM；是持续回收/分配等待下的预防性停止。首个5s冷打包也出现过PSI峰50.87%，原监控未把PSI纳入阈值。后续脚本增加full avg10>20连续10样本停止。停止证据 (historical artifact; not bundled)。
3. CPU packed cache包含分组layout。同布局热命中；换组数需要重新分片/打包，准备耗时会大幅波动。本轮尚未优化跨布局复用，不能只看一步速度推断首次启动/不同token来回切换的端到端耗时。
4. 旧资源脚本total-used含驱动保留（现测529/527MiB），并不是真实free；原E53922/552MiB是差值上界，不能当真实可分配余量，原始数据未采free无法精确追溯。现在改采memory.free。生产auto始终用CUDA预算，未受此显示口径影响。
5. 15s自动测试后段实采free最低约4.61/6.98GiB；该补充采样未覆盖所有早期运行，因此不据此补造5s/10s的真实free最小值。NVML峰值为采样下界，分配器峰值为本配置累计精确计数。资源采样中位约1.16–1.46s、最大间隔2.85s；已记录区间swap-out增量0。
6. Comfy history里的E54_SCAN_COMPLETE是完成回放后主动终止工作流，不是视频生成成功；最后补充对照记录ConnectionResetError来自主动停止测试服务。两卡已恢复1MiB占用，无测试服务残留。
