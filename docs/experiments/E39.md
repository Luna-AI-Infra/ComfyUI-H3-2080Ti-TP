# E39：真实 VAE 单 block FP16/FP32 对照

2026-10-23。父E38/E32，生产代码父540cbd40ab6b98f5b4499c13a3064fdd57dfa706，实验提交见report-commit.txt。仅独立实验，不修改生产节点/启动参数/默认精度。

## 结论

本机ComfyUI明确支持`--fp16-vae`（comfy/cli_args.py第99行），同时提供FP32/BF16选项。但当前自定义H3TPVAEDecode/tp2_precision节点显式构造FP32边界和分配混合精度；仅改变Comfy启动参数不能覆盖这个节点的精度方案。

固定真实block18输入[4,1797,2048]、同一权重、同一双卡TP引擎，输入已在两卡驻留时：FP32 56.323ms，当前混合41.364ms，当前仅FC1半精度27.409ms，FP16 TP17.546ms。FP16 TP相对全FP32为3.210倍，相对当前配置2.357倍。此为单block局部结果，不换算完整VAE或视频端到端加速比。

## 输入与测试口径

重新从当前staged Entry.decode/tp2_precision捕获零起始block18输入和输出，复用E28真实视频latent（896×512、124内部帧），不是旧E30的FP16输入夹具。捕获输入FP32，双卡输入/输出分别逐值相同。block权重从当前VAE FP16 checkpoint加载为FP32；转换FP16没有新增原生FP32权重信息的损失，但会对当前FP32激活重新舍入。输入来自当前混合精度的上游轨迹，不宣称整段VAE全FP32轨迹。

完整tile批次B4/T1797/C2048，是当前480p864×480和720档1280×736共同出现的shape。每卡16 heads，FFN中间维4096。当前混合精度独立block输出与真实捕获输出逐值一致（max_abs=0）。没有随机生成输入或重新生成视频；原latent seed本轮未重新核验。

调用真实VAETensorParallel.run，只将shards列表限制为同一个block；没有另写模型数学公式。所有方案保留实际双线程、事件和两次FP32直接P2P求和，TF32、FP16 reduced-precision reduction与FP16 accumulation开关均关闭。PyTorch2.11.0+cu130/CUDA13.0。

正常计时无profiler：3轮交错顺序，每轮每配置5次预热+10次测量，共30样本/配置；报告整体中位数。墙钟包括线程提交、cast、同步、两次P2P，不包括加载/分片/磁盘读写。权重与输入在计时前驻留。每个配置独立shards与PeerExchange，因而不将本实验总显存占用作为单配置部署显存。

主要口径为两卡输入和RoPE已驻留，模拟36层连续执行中的单层：仅缓存run入口的copy_to副本，block内部实现保持原样。另保留原run入口、包含初次输入复制的完整正常对照；四种配置的两种入口输出均逐值一致。缓存输入仅属于微基准夹具，不是生产优化。

## 精度方案

|配置|QKV/out/FC2|FC1|attention|主激活/Norm/RoPE/SwiGLU|归约与残差|
|---|---|---|---|---|---|
|fp32|FP32|FP32|FP32输入|FP32|FP32|
|current_mixed|FP16输入权重、FP32输出|FP32|FP32输入|FP32|FP32|
|current_fc1_half|同当前|FP16输入权重、FP32输出|FP32输入|FP32边界/SwiGLU|FP32|
|fp16_tp|QKV FP16输出；out/FC2 FP16乘法、FP32部分和|FP16输入权重及输出|FP16输入输出|FP16输入/存储；内部归约精度由算子实现决定|P2P/求和FP32，残差addcmul显式FP32后写回FP16|

FP16 TP不是“所有内部计算都FP16”，保留了既有TP数值路径的FP32归约。attention仍走同一Comfy optimized_attention/PyTorch内存高效后端，仅dtype改变；没有Kitchen/Sage，不改变稀疏率。

## 正常性能和误差

下表误差相对同输入的FP32 TP block输出，属于中间激活误差，不是RGB误差/图像PSNR。

|方案|输入驻留 ms|含入口复制 ms|相对FP32加速|相对当前加速|相对RMSE|最大绝对误差|
|---|---:|---:|---:|---:|---:|---:|
|全 FP32 TP|56.323|56.799|1.000×|0.734×|0|0|
|当前 tp2_precision|41.364|42.091|1.362×|1.000×|2.67936e-05|1.55866e-05|
|当前配置仅 FC1 改半精度乘法|27.409|28.423|2.055×|1.509×|6.40368e-05|4.9293e-05|
|FP16 TP（归约/部分残差运算 FP32）|17.546|17.897|3.210×|2.357×|0.000324771|0.00110555|

FP16 TP相对RMSE为0.032477%，最大绝对误差0.001106；当前混合精度相对RMSE0.002679%。全部输出有限，单次额外重复检查逐值一致。仅降低FC1乘法精度相对当前约1.509倍，误差高于当前，但小于FP16 TP。这是候选方向，不因一个block数值小而晋升；完整VAE可能累积误差，之前E32已见过局部放大。

未锁频；保留原始30次样本和每轮中位数。精度组采用交错顺序缓解温度/频率顺序偏差，但不等同恒定频率硬件基准。

## 独立 Nsight timeline

正常性能和trace分开。Nsight Systems2024.6.2，每方案采3次真实双卡block；4份trace覆盖GPU0/1全部阶段。根据CUDA runtime correlationId和CPU NVTX范围归属GPU kernel，750个kernel全部有阶段归属；72条copy包含入口输入/RoPE复制及两次P2P交换。图取各方案中间一次，灰底是CPU worker范围并包含同步等待，不是CPU纯计算。图中输入复制可能仅露出尾部，不用图宽取代正常墙钟表。

以下是GPU0每次block各阶段kernel累计时长的3次均值，包含该阶段cast/逐元素操作；不同GPU和copy可能重叠，不能把两卡/复制累加成墙钟。

|配置|attention ms|FC1+SwiGLU ms|FC2 ms|
|---|---:|---:|---:|
|全 FP32 TP|8.148|19.056|9.638|

FC1从FP32的volta_sgemm_128x128_tn变为半精度turing_s1688gemm系列。FP16 TP的kernel名称包含relu，但这里调用仍是F.linear；不能仅凭库内部kernel名声称模型插入了ReLU。SwiGLU仍为独立SiLU和乘法kernel。attention从fmha_cutlassF_f32_aligned_64x64_rf_sm75切到f16版本。主要收益来自矩阵乘法和attention精度变化，不是减少P2P次数。

## 失败、存储和恢复

第一次正常测量完成后，保存output-fp32.pt遇到系统盘100%（普通用户可用空间0），torch.save报iostream error，输出文件不完整。failed-disk-full保留状态、日志、原始测时与不完整输出；不使用其成品tensor作为参考。真实输入/权重成功保存且随后与NAS副本SHA256完全一致。

NAS status检查通过，剩余约612GiB。nas-storage脚本只接受Windows本地源，本轮源在Linux x9dai，故通过SSH调用rsync至已挂载NAS，并做源/目标SHA256校验。本地原件全部保留，没有删除源文件。后续所有大张量和报告直接写[redacted path]

NAS恢复后的正常性能/误差成功；首次Nsight使用NFS TMPDIR报Failed to write CUDA config file，保留failed-nsys-tmp。改用已授权root和/dev/shm/h3-e39-nsys内存临时目录后，四份trace成功导出且GPU事件完整。保留首次失败status.json，最终完成状态见completion.json，不能把采集失败误报为模型数值失败。
