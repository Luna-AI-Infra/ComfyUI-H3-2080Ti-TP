## E29：视频 VAE TP2 / FP16 调优完成

父实验 E28，代码父 b72c488。实现 fa4963d（VAE TP）；a560376（NVTX）；c6f3c49（可选 FP32 Norm/残差）；7a58524（混合精度末端 LayerNorm dtype 修复）。未接入常规 ComfyUI 默认流程。

### 固定输入与口径

复用 E28 latent `[1,24,37,32,56]`，解码 `[1,124,512,896,3]`。它来自 E27 FP16 LoRA 视频分支的有限 latent，该次音频存在 NaN；不把它冒充 E27 成功 FP32 LoRA 成片轨迹。只测视频 VAE 解码，包含分块/拼接/输出搬运，不含模型加载、TP 分片准备、主干或采样。模型和两卡分片准备完成后连续测两遍，第二遍仅一条热运行观测，未估计统计置信区间。性能运行与 Nsight 采集运行分开。

### TP 切分与精度开关

ViT3D decoder 共 36 层，D=2048、32 heads、head_dim=64；每卡 16 heads。QKV 按交错 head 行切，输出投影按列切；FFN 原始中间维 8192，gate/value 同索引切，每卡 4096；第二线性层按列切。同 tile 输入在两卡复制，每层 attention 和 FFN 后各一次直接 P2P 求和。不是 tile 数据并行。36 层分片常驻，不涉及主干的三组预取。

真实 tile `[B,24,7,16,16]`，B=4/1 各 21 次，共 42 次。N=7×16×16+5=1797。FP32 部分和消息 `[B,1797,2048]`，每次每方向 B4=58,884,096 bytes、B1=14,721,024 bytes；36 层×2 次×42 tiles。具体通信统计见 trace，而不是把通信字节当权重搬运。

- `--tp`：默认关闭，开启 tensor parallel 两卡。关闭可回到单卡基线。
- `--dtype fp32|fp16`：显式选择权重和 GEMM 输入精度；2080Ti SM75 本轮选 FP16，没有使用 BF16 模拟路径。
- FP16 TP 的 row-parallel GEMM 输出 FP32，跨卡求和、bias、残差 addcmul FP32，再转回 FP16 hidden；FP16 reduced-precision reduction 与 TF32 均关闭。attention 使用 Comfy optimized_attention（本测试 use-pytorch-cross-attention），没有把主干 Kitchen50 稀疏率套给 VAE。
- `--stable`：默认关闭，仅 TP FP16 的实验开关，保留 FP32 Norm、QK Norm/RoPE、残差 hidden，GEMM/attention 仍 FP16。名称不代表已证明更稳定。本次 PSNR 反而降低，不推荐开启。

### 数值与选择

全部输出有限；FP32 TP 与单卡 FP32 相对 RMSE 2.36e-7，最大绝对误差 7.54e-6，完成此输入完整 VAE 数值验证，但不能称逐值一致。单卡 FP16 PSNR 70.88 dB，最大误差 0.03077；TP FP16 PSNR 52.45 dB，最大误差 0.70085，约 0.007705% RGB 元素误差大于 0.1。FP32 Norm/残差补测约 19.96 s、44.04 dB，最大误差 1.0，未改善。

因此速度优先可试 TP FP16 18.32 s，但须做画质消融；更保守的速度/精度平衡是单卡 FP16 25.98 s；需要双卡且尽量维持基准数值则 TP FP32 57.68 s。没有将存在局部大偏差的方案设为默认。原因尚未定位到单一算子；TP 改变 GEMM shape、归约与舍入，不能仅凭这些现象认定某个 kernel 错误。

指标基于解码后 [0,1] RGB（含原流程裁剪），不是裁剪前误差。权威逐帧统计为 `metrics.json`；bench JSON 的旧 worst_frame_index 把 batch 当帧，只保留原记录，不用于逐帧结论。静态对照图不足以证明时序画质无损。完整主干/采样/音视频端到端尚未复测。

### Timeline 与显存

普通 TP FP16 正常运行 18.316 s，profile 窗口 18.669 s；GPU0/1 活跃区间并集占 93.06% / 87.55%。每卡主要计算仍为 FFN；GPU0 FFN FC1+SwiGLU 4.875 s、FC2 2.232 s、QKV 1.768 s、attention 1.726 s、输出投影 0.637 s（kernel 累计，不能直接等同墙钟）。每卡 P2P 约 111 GB 激活求和流量，复制累计约 2.37 s；GPU0 另有约 0.733 s 输出 D2H。正常输出回传 CPU 与两卡 allreduce 不同，allreduce 没走 CPU 中转。

FP16 TP 解码期间 PyTorch allocated 峰值 GPU0/1=3348/2860 MiB，FP32 TP=6541/5587 MiB；不是 nvidia-smi 总显存，也不包含正常整图同时驻留的主干需求。准备阶段峰值单独记在 JSON。

完整 timeline、100 ms 放大、phase/hotspot CSV、原始 trace 和数值结果均关联本实验。CPU API 包含等待，CPU/GPU/复制重叠不能相加当端到端时间。
